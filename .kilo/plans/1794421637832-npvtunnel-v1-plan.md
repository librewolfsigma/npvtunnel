# NPVTunnel v1.0 — Implementation Plan

## Goal
A lightweight, security-hardened native Windows desktop GUI for NPVTunnel that:
- Opens with no terminal/console window (`windows_subsystem = "windows"` — already done)
- Auto-adds `.npvt` files on double-click via a per-user in-app file association (no installer, no elevation)
- Fixes all enumerated npvtunnel security defects
- Ships "all features": TUN mode, kill switch, per-process routing, tray mode
- Is built from the existing Rust workspace (`npvt-core` + `npvt-cli` + `npvt-gui`) using the bundled sing-box sidecar engine

## Decisions resolved
| Decision | Choice |
|---|---|
| Release scope | B — go big v1.0 (all features: P3 hardening + P4/P5 TUN/kill-switch/per-process-routing) |
| `.npvt` file association | A — in-app per-user `HKCU` association only; no MSI/installer in v1.0 |
| TUN / kill switch / per-process routing | A — sing-box native TUN (admin-gated, reuses existing engine); kill switch via Windows Firewall rules; per-process routing via sing-box routing rules |
| Code signing (Authenticode) | B — optional/deferred; v1.0 ships unsigned with SmartScreen "Run anyway"; signing added later when a cert budget exists |

## Security defects to fix in v1.0
Enumerated from SECURITY.md "known limitations" + code review:
1. **Vault at rest is plaintext JSON** — no DPAPI / owner-only ACL on Windows. Fix: enforce owner-only ACL on `vault.json`, `engine.json`, `engine.log`, `engine.pid` on Windows; add DPAPI-encrypted credential wrapper as a follow-up if feasible.
2. **Engine config/log/pid files not owner-only on Windows** — `write_config` only chmods 0600 on Unix. Fix: set Windows owner-only DACL on all engine sidecar files.
3. **Bundled sing-box binary not authenticity-verified** — anyone could swap `sing-box.exe`. Fix: at startup, compute SHA-256 of the bundled sing-box and compare to a pinned checksum embedded at build time; refuse to run on mismatch.
4. **clash API on localhost with no auth** — any local process can read traffic stats. Fix: keep bound to `127.0.0.1` (already done); add an optional auth token read from settings; gate traffic stats behind it.
5. **Session/pid-file liveness via tasklist parsing** — weak. Fix: keep exact-quoted-CSV matching (already done); add a named mutex lock on the session file to prevent double-start.
6. **No memory locking for credentials** — keys/passwords pageable to disk. Fix: best-effort `VirtualLock` on Windows for in-memory credential buffers (Zeroize already on drop).

## Ordered task list

### Phase 1 — File association + tray (P3 core)
1. Add a registry helper module in `npvt-gui`: read/write `HKCU\Software\Classes\.npvt` and the `shell\open\command` pointing at `NPVTunnel.exe "%1"`.
2. Add an "Associate .npvt files" button on the More page; on click write the association and show success/already-associated state.
3. Handle `NPVTunnel.exe <file>` launch: if invoked with a `.npvt` path, open the import security card for that file (same as Configs -> Add).
4. Add tray mode: minimize-to-tray icon, show/hide window, "Disconnect & quit" that stops the shared engine session.

### Phase 2 — TUN mode, kill switch, per-process routing (P4/P5)
5. Extend `npvt-core::engine::config` to emit a TUN inbound (and/or mixed socks+tun) when TUN mode is enabled; add TUN toggle in GUI More page, admin-gated with elevation prompt.
6. Add kill switch: on connect, add Windows Firewall rules blocking outbound traffic except to the sing-box SOCKS/TUN local inbound; on disconnect, remove rules.
7. Add per-process routing: process-based routing rules in the sing-box config (forced direct / forced proxy) configurable per profile or globally.

### Phase 3 — Security hardening (defects 1–6)
8. Windows owner-only ACL helper; apply to vault, engine config, engine log, pid file on every write.
9. Embed pinned SHA-256 of the bundled sing-box at build time; verify at startup in `find_engine_binary` / GUI engine-detection; refuse on mismatch.
10. Add optional clash-API auth token in settings; gate `/connections` polling.
11. Add named-mutex lock around session file to prevent double engine start.
12. Best-effort `VirtualLock` on credential buffers in memory (Windows).

### Phase 4 — Polish, tests, validation
13. Add unit/integration tests for registry association, ACL setting, checksum verification, TUN config rendering, firewall-rule generation.
14. Run `cargo fmt`, `cargo clippy -D warnings`, `cargo test` on the workspace.
15. Build `cargo build --release` for `x86_64-pc-windows-msvc`; verify `NPVTunnel.exe` launches with no console.
16. Manual validation: double-click a `.npvt` file imports; connect works; tray minimize/restore works; TUN connects as admin; kill switch blocks traffic when on; checksum verification rejects a tampered sing-box.

## Risks
- **TUN mode requires admin** on Windows; the app must elevate or fail gracefully with a clear message.
- **sing-box TUN on Windows** may have its own driver/WFP requirements; verify sing-box version supports Windows TUN before committing.
- **Per-process routing** via sing-box routing rules may not cover all Windows process-to-socket mapping; scope may need narrowing to "per-profile routing" if process-level proves unreliable.
- **Firewall kill switch** rules require admin and may conflict with third-party firewalls/VPNs.

## Validation
- `cargo test` passes across all three crates.
- `cargo clippy -D warnings` and `cargo fmt --check` clean.
- Release build produces `target/release/NPVTunnel.exe` (GUI, no console) and `target/release/npvt-cli.exe`.
- Manual end-to-end: `.npvt` double-click → import card → connect → traffic stats → tray → disconnect → quit.

## Out of scope for v1.0
- Code signing / Authenticode (deferred, see decision above).
- MSI / Inno Setup installer (per-user in-app association only).
- DPAPI-encrypted vault (post-v1.0 follow-up).
- winget / MSI GA channels (P4/P5 packaging).
- WFP filter driver (sing-box native TUN chosen instead).
